3. Mentoring & Counseling Activity Layer
mentoring_sessions (Interaction Ledger)
Tracks communication and mentoring frequency. Essential for institutional compliance reports showing whether mentors are meeting their allocated student quotas.

id (INT, Primary Key)

relation_id (INT, ForeignKey links to mentorship_relations.id)

session_date (DATETIME): Timestamp when the review took place.

discussion_summary (TEXT): Encrypted or plain text summary of progress notes.

action_items (TEXT): Deadlines or targets set for the student.

category (VARCHAR): ENUM ('Routine Academic Review', 'Disciplinary', 'Career Counseling').

counseling_escalations (Critical Cases)
Tracks students referred to professional psychological counselors or head administrators for special interventions.

id (INT, Primary Key)

student_id (INT, ForeignKey links to users.id)

referred_by_id (INT, ForeignKey links to users.id)

counselor_id (INT, ForeignKey links to users.id, Nullable)

escalation_reason (TEXT): Context regarding why academic thresholds failed to correct behavior.

resolution_status (VARCHAR): ENUM ('Pending', 'Under Review', 'Resolved').

4. Configuration & Security Metadata Layer
system_configurations (Multi-Tenant Threshold Thresholds)
Rather than hardcoding academic failure values, this table dynamically dictates what triggers alert flags in reports based on the department or institution.

id (INT, Primary Key)

department (VARCHAR): Unique target domain (e.g., "Global", "Computer Science").

attendance_threshold (FLOAT): Minimum required attendance percentage (e.g., 75.0).

cgpa_threshold (FLOAT): Minimum expected passing CGPA baseline (e.g., 6.5).

term_name (VARCHAR): Current active operational term context string.

audit_logs (Security & Accountability Tracking)
Crucial for institutional audit data, proving who altered records, when batch processes executed, and validating compliance.

id (INT, Primary Key)

timestamp (DATETIME): Auto-generated database entry server time.

user_id (INT, ForeignKey links to users.id): The entity who initiated the action.

event_type (VARCHAR): ENUM ('ACCOUNT_PROVISION', 'PASSWORD_MUTATION', 'BATCH_CSV_UPLOAD').

details (TEXT): String describing exactly what row data changed.

ip_address (VARCHAR): Network tracer metadata.

    id SERIAL PRIMARY KEY,
    -- Reference key tracking back to the primary unique system identifier
    student_id VARCHAR(50) UNIQUE NOT NULL,
    
    -- Academic Position Shifting States
    current_year INT DEFAULT 1,       -- 1, 2, 3, 4
    current_semester INT DEFAULT 1,   -- 1 through 8
    
    -- Safeguard Tracking State & Multi-Run Protection
    last_advanced_academic_year VARCHAR(50) DEFAULT NULL, -- e.g., '2026-2027'
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,

    CONSTRAINT fk_academic_user FOREIGN KEY (student_id) 
        REFERENCES users(usn_or_id) ON DELETE CASCADE
);

-- 1. Safely drop the old table configuration if it exists to clean out old constraints
DROP TABLE IF EXISTS clinical_knowledge_base CASCADE;

-- 2. Create the entire optimized clinical_knowledge_base table structure
CREATE TABLE clinical_knowledge_base (
    id SERIAL PRIMARY KEY,
    domain VARCHAR(50) NOT NULL,                 -- Matches 'psychology', 'mental_health', or 'relationships'
    keyword_combinations TEXT NOT NULL,          -- Houses your rich natural language query scenarios 
    predefined_title VARCHAR(255) NOT NULL,      -- Header matching rule configurations
    predefined_answer TEXT NOT NULL,             -- Bullet-parsed content blocks pre-split with "->"
    severity_tier INT DEFAULT 1,                 -- Triage classification parameter
    action_url TEXT,                             -- Support destination redirect link

    -- 3. CRITICAL: The dynamically computed full-text query column vector
    -- This merges your conversational keywords and title strings, ignoring useless words, 
    -- and turns them into a structured text document format that Postgres can rank mathematically.
    search_vector tsvector GENERATED ALWAYS AS (
        to_tsvector('english', coalesce(keyword_combinations, '') || ' ' || coalesce(predefined_title, ''))
    ) STORED
);

-- 4. Build a high-performance GIN (Generalized Inverted Index) over the search vector column
-- This keeps lookups running instantly even with 3,000+ entries, avoiding slow sequential table scans.
CREATE INDEX IF NOT EXISTS idx_search_vector 
ON clinical_knowledge_base USING gin(search_vector);
